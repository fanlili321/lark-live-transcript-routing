# 直播文字稿整理规则

来源：飞书知识库《【规则】直播课文字稿整理》 `https://epndqwwg0a.feishu.cn/wiki/BqGHwjDa2iciA8krDwVcRePVns4`（docx token `CpWPdz9ilob1jrxiKd2cfBuYntf`）。规则以该文档为准，若两者不一致以云文档最新版本为准，可定期用 `docs +fetch` 复核并更新本文件。

## 整体结构

文字稿分两部分：
- 第一部分：PPT 讲解环节，从开头到问答开始之前
- 第二部分：互动环节（问答），文字稿里通常有明确提示，如"进入到今天的互动环节"

整理完成后追加"三、总结"部分，并在开头补目录（见下方"目录"小节的限制）。

## 段落调整

- 意群划分：介绍同一话题的几句话归为一段，按内容表达完整性分段，每个意群表达完整后空一行
- 段落长度：每个意群控制在 4-5 句话，避免仅 2-3 句的短段落
- 断句标准：以句号"。"和问号"？"作为句子结束的判断标准
- 不同段落之间空一行（保留空 `<p>`）

## 表述规范

### 年份表述
- 基准年为当年（执行时按当前日期取年份，如 2026 年执行则今年=2026，去年=2025）
- 年份补全：两位数简写补全为完整年份，如"13-14年"→"2013-2014年"、"03年"→"2003年"、"08年"→"2008年"、"09年四万亿"→"2009年四万亿"、"17-18年"→"2017-2018年"
- 结合上下文语义（非典、金融危机、四万亿等历史事件）判断具体世纪，不要机械补全
- 保留原文"今年""今天"等相对时间表述，无需替换为绝对年份
- **多个年份连续列举、只有最后一个数带"年"字的复合写法容易漏改**，例如"22、23、24，科技成长股腰斩"（三个数只有语境暗示是年份，没有任何一个字面带"年"）、"跟十多年前14、2015年没啥变化"（"14"没被识别为"2014"）。这类不能靠通读时凭印象留意——2026-08-07 在23期抓到一处漏改后写了"通读时留意"的提醒，467期又漏了一处（同样的复合列表模式，只是数字不同），说明"读的时候多留意"这种提醒本身不可靠，容易在赶进度时被跳过。**改为强制的机械自查步骤**：整理完成自查阶段，专门用类似 `\d{1,4}(?:[、，,]\d{1,4})+年` 的模式对全文做一次正则扫描，把所有"数字+顿号/逗号+…+数字+年"的复合列表结构都找出来，逐个核对列表里每一项是不是都补全成了4位年份（不是只看最后一项带"年"字的那个）；不要只在读稿子的过程中靠肉眼扫，扫描必须作为一个独立的、可重复执行的步骤。
- **来源文本如果是通过 `docs +fetch --doc-format markdown` 读取的（高净值流程读"文字记录"文档时如此），markdown 转义会在源文本里留下字面反斜杠**，最常见的是区间号"~"被转成`\~`（如"3\~5年"）。这些反斜杠如果直接原样抄进新文档，会在正文里露出来，读者会觉得很怪（2026-08-07 领导复核发现的）。写入新文档前，或整理完成后自查阶段，全文查一遍字面反斜杠字符，统一去掉（`\~`→`~`），不要假设 markdown 抓取的文本已经是"干净"的可以直接用。

### 螺丝钉术语
- "365""90"等简写，指"365天组合""90天组合"，需补充完整
- "X星"是螺丝钉星级表述（如"3星级""4点几星"），不需修改
- "固收+"/"固收"/"固收加"/"固收家"统一表述为「固收+」

### 问答字数统计

- **必须用官方脚本统计，禁止拿字符长度（如 Python `len()`）顶替**：`../lark-doc/scripts/doc_word_stat.py` 才是飞书文档"字数统计"的口径（英文按单词算、贴着英文的英文标点不计入等），直接数字符会把每个英文字母、每个标点都算 1 个字，数值明显偏高，跟人工/飞书 UI 看到的对不上（2026-08-07 领导复核就是因为这个被指出"字数略微不准确"）。
- 用法：把该问题的正文内容包成 `<p>...</p>` 拼接的 XML 片段，`cat fragment.xml | python3 ../lark-doc/scripts/doc_word_stat.py --protocol xml`，读输出里的 `word_count` 字段（不是 `char_count`）。
- **在所有文字修改（分段、表述规范、语气词删除等）都完成之后，作为最后一步统一计算**，不要在中途某个阶段就把字数定死——后续任何编辑都会让数字过期。
- 不遗漏任何段落，逐题统计，写入该问题标题的 `（{字数}字）`。

## 编辑原则

- 基本原则：不随意删减原文重点表述内容，保持原意完整
- 删改原则：不过度删除原文内容，一般情况下输入和输出字数大体要保持一致
- 允许删除：不影响原文大意的语气词；明显的磕绊、忘词、重复表述

### 语气词删除的具体做法（2026-08-07 领导复核后固化，同日二次复核补充，2026-08-08 三度补充）

- **删除对象是"语气词"这一整类，不是某一次反馈里点名的那几个字**：目前已知常见的至少有"呢""啊""诶""哈""哎"。第一次只删了被点名的"呢""啊"，结果"诶"（15处）没删被打回来一次；第二期又漏了"哎"（13处）被打回来第二次——**这个模式已经出现两次了，说明"等被点名再删"这个做法本身就是错的**。以后处理任何一期新文字稿，第一步整理时就主动做一遍全量语气词扫描（至少涵盖呢/啊/诶/哈/哎这五个，外加通读时留意有没有其他新的），不要只删上一期被点过名的那几个就当完成了。
- 匹配范围：紧跟在逗号、句号前的用法（"呢，""呢。""啊，""啊。""诶，""诶。""哈，""哈。""哎，""哎。"）。这类几乎 100% 可以整段删除而不影响语义。
- **不要删**："呢？""啊？"（表疑问语气的用法，如"这该怎么办呢？"）——去掉会破坏语法，必须保留。
- **做法**：不要逐处人工判断再删，直接用 `docs +update --command str_replace` 做全文查找替换，每个语气词的每种标点组合各跑一条（如 `--pattern "呢，" --content "，"`），`str_replace` 是全文替换、且不改变 block ID（不会破坏已有批注锚点）。这类语气词经常整篇出现两三百次（本身语速快、口语化的直播稿尤其多），逐句人工删效率低、也容易漏，交给全文替换更可靠。
- **批量替换完成后必须自查标点连缀问题**：语气词有时出现在句号之后（新句子开头的口头禅，如"……跌幅。呢，在下跌之后……"），此时按"呢，"→"，"替换，句号后会留下一个孤立的逗号（"。，"），是明显的标点错误（2026-08-07 二次复核就抓到过一处）。每次批量删完语气词，要专门全文搜一遍 `。，`、`，，`、`？，` 这类连续标点组合，自己发现自己改，不要留给复核的人挑。

### 收尾前自查：重复句/口误

- 逐字稿常见说话人自己重复了一遍前半句（例如"比较合理的，比较合理的融资盘的规模"、"第三种的方式，第三种的方式呢，是做赎回的操作"），这类原文本身的口误容易在整理时被忽略（因为读起来语义连贯，不像错别字那样扎眼）。
- 定稿前专门过一遍：搜索文档里"逗号前后紧邻重复的 3-6 字短语"这种模式，去重只保留一次。不要假设已经在分段/表述规范那一步顺带处理掉了。

遇到清单外但明显的错别字/数字错误，通读全文时一并订正；不确定是口误还是术语时保留原文，不要臆测替换。

**产品/工具/小程序名称，以 PPT 上写的为准**（2026-08-08 领导复核发现）：王磊口播时对同一个产品的称呼有时会说错、说漏字，比如某一期把"今天几星"小程序说成了"今天基金"，一篇稿子里有的地方对、有的地方错。这类不是清单能穷举的固定错别字，而是每期都可能出现的口误。核对方法：PPT 里出现的名称（尤其是产品名、小程序名、App 名这种专有名词）视为准确来源，通读全文时用 PPT 上的名称去对一遍文字稿里所有提到同一事物的地方，不一致的以 PPT 为准统一改掉。

## PPT 图片

- 根据文稿内容逻辑，在对应解释这页 PPT 的文字**之前**插入图片
- 需准确识别 PPT 标题，按关键词首次出现位置匹配（本 skill 已实现为直接插入真实截图并用 `block_move_after` 定位，比人工规则里"仅文字标注【PPT第X页：标题】"更进一步，保持现有插入实现，不要退化成纯文字标注）
- **除总结页外，PPT 图片默认全部在"一、讲解部分"，按 PPT 页码顺序插入，问答部分不放图**：直播是从头到尾按 PPT 页码顺序讲下来的，图的位置跟"这页 PPT 出现的原始顺序"绑定，不是跟"关键词在全文哪里出现"绑定。
  - **反面教训（2026-08-06）**：曾经按关键词把两页 PPT（一页讲"私募增厚收益的具体方式"、一页讲"1对1投资机会提醒服务"）匹配到了问答部分里关键词命中的段落，结果被领导指出"图插错位置了，应该在前面讲解部分"——关键词在问答部分里出现过，不代表这页 PPT 是在问答环节放的；PPT 只会按页码顺序在讲解部分放映一次。
  - 正确做法：先按页码顺序把所有图分配到讲解部分对应位置；只有明确找不到任何讲解部分的文字线索、又必须要放的极少数情况，才考虑问答部分，并且要打个问号跟用户确认，不要自己决定。
  - **"找不到对应文字"经常是关键词试少了，不是真的没有**（2026-08-07 二次复核）：第20页"1对1投资机会提醒服务"这张图，第一次判断为"没有明显对应文字"，直接按页码顺序随便找了个相邻位置凑数；结果原文里其实有一句明确写着"可以扫描这个二维码……投资机会提醒"，只是换个说法、没有逐字匹配上标题。定位一张图时，要拿这几类词都试一遍再下结论：图的大标题、图里每个小标题/加粗词、图里出现的具体名词（如"二维码""扫码"这种大概率会在原话里出现的动作型词），只试一两个关键词没搜到就判定"无对应"是不够的。
- **一张图如果对应的原文段落里混了两个不相关的话题**（比如同一段前半句在讲别的、后半句才讲到这张图对应的内容），不要因为"图只能插在整段前面"就把图插到不相关的那半句前面。应该把这一段按话题拆成两个独立段落（先用 `str_replace --content ""` 从原 block 里删掉要拆出去的后半句文字，保留原 block 只剩前半句，再用 `block_insert_after` 把后半句作为新段落插回去），再把图插在拆出来的新段落前面，保证图真正贴着它对应的那句话。
- **匹配到"含相关内容的段落"不等于匹配对了位置，要找到那句真正的引子**（2026-08-08 复核发现）：467期"不同星级买入持有到期末对应年化收益率"这张图，一开始匹配到了段落中部提到具体百分比数字的位置，但其实这段话前面还有一句"这个数据里边有几个比较典型的特征"，是讲者真正开始解说这张图的地方，图应该插在那句话前面，而不是插在后面某处刚好出现匹配数字的地方。定位一张图的位置时，优先找"接下来看""这个数据""这张图""这几个特征"这类明确的引入句，而不是随便命中几个数字或关键词就下结论；数字/关键词只用来定位到大致段落，句子层面的精确位置还要再核实一遍。
- **绝对不要把两张图放在同一个位置、之间没有隔任何文字**（2026-08-08 复核发现，属于硬性规则，不是建议）：直播是对每一页 PPT 分别讲解的，两张图之间必然有对应的讲解文字，图片紧挨着图片这种情况在原始逐字稿里不会出现。如果处理下来发现两张图"只能"插在同一个锚点，说明是没有为其中至少一张图找到它真正对应的那段文字——回去按上面几条重新搜（多试几个关键词、检查是不是两个话题混在了一个段落里要拆开），直到两张图之间有真实原文分隔，不要接受"先凑合放一起"的结果。整理完成自查阶段要专门查一遍是否存在相邻两个 `<img>` block 中间没有夹 `<p>` 的情况。

## 提炼互动环节问题

- 讲解/问答边界：讲解部分持续到出现"进入到今天的互动环节"一类提示，或第 1 个【有朋友问】标记出现之前
- 总结边界：出现"今天的直播到这里就要结束了"一类收尾语（具体措辞因期数而异，按语义判断，不要死等固定字符串）之后归入"三、总结"
- 问题标记：以【有朋友问】开头（变体：【有投资者问】【有客户问】），例如"有朋友问港股的中概科技现在在低估吗？"→ 问题即"港股的中概科技现在在低估吗？"
- 答案范围：从该问题标记到下一个问题标记（或总结部分开始）之间的所有段落

## 设置小标题

- H1，固定三个：
  1. 一、讲解部分
  2. 二、问答部分
  3. 三、总结
- H2，问答部分每个问题一个：
  - 格式：`{序号}. {问题}（{字数}字）`
  - 序号从 1 开始按出现顺序编号
  - 字数为该问题对应回答的全文字数
  - 回答内容系统、有可能作为文章选题的问题：标题前加 ⭐️，问题文字标红

## 目录

- 文档开头需要目录小组件，方便浏览、点击跳转
- **已知限制**：飞书文档 API 不支持创建 readonly-block 类型的目录组件，无法自动插入；整理完成后在私聊知会消息里提示当前执行者手动添加，或跳过，不要假装已完成

## 完成标记

- 2026-08-07 起不再有 `_原文` 中间态：文档创建时直接用最终标题（三种类型各自的命名格式见 `references/config.md`），不需要整理完成后再改名。
- "是否已整理完成"靠实际检查段落、标题、错别字、图片位置是否都按规则处理过，不再靠标题有没有某个后缀来判断；不要另外新建一份"整理稿"副本。
